# 足球预测分析系统 · 架构文档

## 系统总览: 五层预测流水线

```
L0 数据基础层 → L1 赛前分析层 → L2 预测引擎层 → L3 输出验证层 → L4 赛后审计层
```

---

## L0: 数据基础层 (8个模块)

### 球队身份
- **team_registry.py** — 统一球队ID库, 25+队注册, 消除跨联赛译名/简称不一致
- 同一支球队的所有别名映射到唯一ID: "费内巴切" = "Fenerbahce" = "Fenerbahçe" → `CLQ_FEN`
- 解决: 开云体育/API-Football/我们模型之间的队名不匹配

### 联赛画像
- **league_profiles.py** — 15个联赛独立画像
- 每个联赛: 主场胜率, 平局率, 场均进球, 大2.5率, 角球, ELO主场加成
- 欧冠资格赛 (CLQ): 主场ELO+60 (非通用+100), 主场胜率仅40%, 平局率28%
- 解决: 通用模板套所有联赛导致的主场系统性高估

### 赔率数据
- **api_client.py** — API-Football (首选) / football-data.org / 模拟数据 三层降级
- **kambi_client.py** — Kambi博彩公司赔率 (Unibet/888/Betway等), 取中位数作共识
- **tools/odds.py** — The Odds API (40+博彩公司, Pinnacle基准)
- 解决: 赔率来源多样化, 交叉验证

### 数据治理
- **cold_start.py::DataLayers** — L0原始库(只读)→L1特征库→L2快照库 三层隔离
- L0原始历史赛果: 只追加不修改, 内容哈希锁定
- L1特征: 从L0派生, 可删除重建
- L2快照: 每日三时段赔率+预测
- 解决: 防止人为回溯篡改数据

### 冷启动
- **cold_start.py::ColdStartEngine** — 新球队3场衰减缓冲
- 初始攻防值 = 同联赛同层级梯队均值 (非凭空捏造)
- 每场赛后动态修正, 单次幅度上限±15%
- 置信权重: 0.30→0.55→0.80→1.00
- 解决: 欧冠新军/升班马缺少历史数据导致的预测偏差

## L1: 赛前分析层 (6个维度)

### 每日三时段追踪
```
09:00  初盘记录 → 拉赔率 + ELO差 + 联赛画像
16:00  午盘检测 → 对比初盘, 发现蒸汽移动 + 盘口变化
22:00  终盘预测 → 完整分析链 → 6维输出 + 自动下注
```

### 证据包构建
- **evidence_packet.py** — 单场比赛不可篡改时间戳证据链
- 多时间节点快照: T-24h → T-6h → lineup → 开球前freeze
- 所有数据保留来源+观察时间+抓取时间
- 新信息创建新快照, 不修改旧快照
- 缺失数据明确标注 → 不确定性保留在结果中

### 六维预测输出
```
① 胜平负 (1X2)
② 波胆 → 改为"总球区间"
③ 全场大小球 (O/U 2.5)
④ 上半场大小球 + 下半场大小球
⑤ 上半场让球 + 下半场让球
⑥ 角球 (基于真实博彩公司盘口, 如TotalCorner)
```

## L2: 预测引擎层 (5+2个模型)

### 五底座并行体系
| 底座 | 方法 | 特点 |
|------|------|------|
| **B0** | 固定泊松分区 | 无先验, 无市场, 纯攻防力λ |
| **B1+** | 历史先验+市场软约束 | Dirichlet联赛画像先验, 贝叶斯融合 |
| **B2-RC** | 按W/D/L重建 | 分割后独立计算, 防1-1跨结果污染 |
| **P_CANDIDATE** | 自适应融合 | 反集中度动态权重, Herfindahl阈值保护 |
| **Xalpha** | 纯市场信号 | 无球队ELO, 只看赔率+联赛结构偏移 |

五底座非多数表决。同一场比赛/同一证据/同一冻结时刻下并行输出。
连续样本足够前, 不提前确定领先者或淘汰顺序。

### 两个融合层
- **bayesian.py** — 模型先验 × 市场似然 → Dirichlet后验
- **odds_analyzer.py** — 赔率→Shin去水→隐含概率→价值检测→凯利值

### 两个模拟器
- **prediction.py** — 泊松分布经典预测 (ELO+攻防力→λ→比分矩阵)
- **tools/simulate.py** — 蒙特卡洛10000次泊松采样 (置信区间+精确比分+半场分解)

### ELO系统
- **elo.py** — 30+球队初始ELO, 主客场加分, 净胜球加权, 贝叶斯动态更新

## L3: 输出验证层 (3个评估机制)

### 基线对比
- **baseline.py** — 联赛均值基线: "闭眼猜联赛平均"的预测
- 任何模型必须优于基线才可部署
- Brier > 基线Brier → 模型在学噪声, 应回退

### 锁箱评估
- **evaluation.py** — 只用未参与训练的延后赛事验证
- 评估指标: Brier Score, Log Loss, 准确率, 校准曲线, 主场偏差, 平局偏差, 过度自信
- 不改参数, 只输出结论
- 2026.08.04实测: 模型Brier 0.77 > 基线 0.65, **不如闭眼猜**

### 结构塌陷诊断
- **five_bases.py** — 检测1-1过度集中 (Herfindahl > 0.15)
- 修复: B2-RC按W/D/L重建将1-1从10.9%降至2.5%
- 原则: 降排名不是成功标准, 概率转移≠消除异常

---

## L4: 赛后审计层 (3个约束)

### 冻结规则
- 开球前预设截止时间, 所有证据封进赛前快照
- 必须输出完整比分分布, 即使证据不足
- 证据不足→体现更高不确定性, 不能编造信息

### 不可修改
- 开球后首发变化/临场事件/最终比分→不能回溯修改预测
- 赛后只能追加审计记录, 不修改冻结预测
- 发现输入错误→新增更正记录, 不修改原始文件

### 复盘指标
| 指标 | 目标 | 8/4实际 |
|------|:---:|:---:|
| 命中率 | ≥60% | 50% |
| Brier | ≤0.18 | 0.77 ❌ |
| ROI | ≥+10% | -8.5% |
| 优于基线 | 是 | 否(-12%) |
| 1-1集中度 | <15% | — |

## 分析一场比赛的完整逻辑链

```
每一场预测 = 以下22条证据的加权综合:

═══ 定量层 (自动计算) ═══
[1] ELO差 → 进攻力/防守力指数
[2] 联赛画像 → 自适应参数 (CLQ:ELO+60, 非+100)
[3] 泊松λ → 主/客预期进球
[4] 蒙特卡洛 → 胜平负% + 比分分布 + 置信区间
[5] Shin去水 → 市场隐含概率
[6] 贝叶斯融合 → 模型先验 × 市场似然 → 后验
[7] 蒸汽移动 → 有/无, 方向, 幅度
[8] 五底座并行 → B0/B1+/B2-RC/P_CANDIDATE/Xalpha

═══ 情境层 (需手动判断) ═══
[9] 赛程密度 → N天N场, 对手休息天数
[10] 旅途消耗 → 距离km, 时差
[11] 阵容完整 → 核心缺阵, 伤停人数
[12] 场地因素 → 天然草/人工草, 海拔, 天气
[13] 杯赛阶段 → 资格赛/小组/淘汰赛, 首/次回合
[14] 战意评估 → 必须赢/保平即可/无压力
[15] 中立场地 → 主场ELO归零

═══ 市场质量层 ═══
[16] 赔率离散度 → 高共识/分歧/严重分歧
[17] 博彩公司数 → 流动性
[18] Pinnacle偏差 → 专业资金信号
[19] 亚盘vs欧赔 → 一致/背离 (背离→亚盘优先)
[20] 大小球盘 → 初→临, 升/降

═══ 历史校验层 ═══
[21] 同类比赛 → 同联赛画像的历史胜率
[22] 新球队标记 → 冷启动衰减缓冲 (前3场)

═══ 最终输出 ═══
├─ 六维预测 (方向/球数/大小/半场/角球/波胆)
├─ 投注台账 (每场100, 自动下注)
├─ 基线对比 (优于/劣于联赛均值)
├─ 锁箱Brier (实际赛果后计算)
└─ 赛后审计 (只追加, 不修改)
```

## 关键权重优先级

| 权重 | 信号 | 验证来源 |
|:---:|------|----------|
| 1.5x | 蒸汽移动 (>8%骤降) | 8/4复盘: 1/1准确 |
| 1.3x | 联赛画像自适应 | CLQ主场+60修正了系统性高估 |
| 1.2x | 亚盘vs欧赔背离 | 斯巴达案例验证 |
| 1.0x | ELO差 >60 | 基线 |
| 0.8x | 伤缺信息 | NEC案例打脸→降权 |
| 0.7x | 低置信方向 → 强制大小球 | 大小球67% vs 方向33% |
