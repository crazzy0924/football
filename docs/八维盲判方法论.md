# 八维盲判方法论 (国家队版)

创建: 2026-09-24 · 用户拍板方向: **要一个有自己的预测方式的"足球大师", 不要一个复述赔率的智能体**
入口: `python national/octa.py --date YYYY-MM-DD --repeats 3`
自检: `python national/check_calls.py --date YYYY-MM-DD`

---

## 0. 一句话

**先形成判断, 再看价格。** 而不是先看价格, 再解释价格。

## 1. 为什么不是"把市场权重调低"

第一版想法是把八维里"市场"的权重从 20 降到 5。**这个想法是错的, 而且错得很具体。**

同一天我们刚查明: 挪威 vs 丹麦那场, **市场是对的**, 我们错在没看到"丹麦危机 + 埃里克森缺阵"。
给市场降权只会让我们在**已经证明自己是错的那一类判断上**更自信。

真正的问题不是权重, 是**顺序**。现有框架 (见 `pipeline/analyst.py`) 是:
- 把赔率直接塞进证据包, 维度1 就叫"市场"
- 还有一条硬规则: *"若情报/赔率变动/一致性预警中至少两方同向反对当前最高概率方向, 必须下调方向分"*

**有那条规则在, 提示词怎么写都会滑回市场。** 那不叫分析, 那叫解释赔率。

## 2. 两段式盲判

| 段 | 做什么 | 关键约束 |
|---|---|---|
| **第一段** | **遮住赔率**做八维, 跑 K 次取多数 | 市场维度权重 = 0; 证据包里**没有任何赔率数字** |
| **第二段** | 揭开赔率, 对照 | **默认立场是"我的判断成立"**; 只允许因"市场揭示了一个我确实漏掉的具体事实"而改判, 且必须白纸黑字写下那个事实 |
| **第三段** | 落账 | 赛前锁死, 赛后打分 |

第二段**明文禁止**的改判理由 (写进提示词了):
- "市场更有信息优势" / "庄家不会错" / "赔率这么开一定有道理"  —— 这些不是事实, 是借口
- "为了稳健起见" / "降低风险"                                    —— 不许对冲
- 只是因为我上一轮给的方向概率偏低                                     —— 那叫复盘, 不叫改判

## 3. 八维权重 (国家队版)

| 维度 | 权重 | 理由 |
|---|---|---|
| 状态攻防 | 22 | 模型 / ELO / 近期战绩 |
| **阵容伤停** | **24** | **我们的差异化信息几乎全在这** |
| 交锋克制 | 8 | 换帅/大换血时必须**主动降权** |
| 赛程体能 | 8 | 已用 15,620 场证明休息差分无信号, 保留为背景 |
| 天气场地 | 7 | 多数时候抓不到 |
| 裁判 | 5 | 基本抓不到 |
| **战意轮换** | **26** | 本届挂钩 2028 欧洲杯附加赛, 升降级有实质代价; **模型完全无此信号** |
| 市场 | **0 (第一段) / 对照 (第二段)** | 不参与第一段的方向分 |

合计 100。

## 4. 自洽性投票 (2026-09-24 实测逼出来的)

**问题**: 同一份证据连跑 5 次, 意大利 vs 比利时给出了**三种不同结论** (客胜 / 主胜 / 平局)。
—— 一个不稳定的判断不是判断。

**修法不是把温度调低了事**(那只是把噪音藏起来), 而是**把不稳定性变成一个测量值**:

- 第一段跑 K 次 (默认 3), 取**多数派**作为判断
- 多数派里取**方向分中位数**的那一次, 不取极端
- **一致度 (n/K) 直接写进台账**, 并压进最终置信度

温度同时从 0.7 降到 0.35。修后实测 (2026-09-24, 6 场):

| 场次 | 三次盲判 | 一致度 |
|---|---|---|
| 葡萄牙 vs 威尔士 | 主胜 ×3 | 3/3 |
| 荷兰 vs 德国 | 主胜 ×3 | 3/3 |
| 塞尔维亚 vs 希腊 | 客胜 ×3 | 3/3 |
| 挪威 vs 丹麦 | 主胜 ×3 | 3/3 |
| 意大利 vs 比利时 | 平局 ×2 / 客胜 ×1 | **2/3** |
| 土耳其 vs 法国 | 客胜 ×3 | 3/3 |

⚠️ **但这只是一次测量, 样本是 6 场。** "稳定"目前是观察, 不是结论。

## 5. 自检 C1–C6 (`national/check_calls.py`)

每次跑完 `octa.py` 必须过一遍。它是**真的抓到过东西的**, 不是摆设:

| 项 | 内容 | 首次运行的战绩 |
|---|---|---|
| C1 | 七维恰好 7 项、顺序固定、权重合计 = 100 | 通过 |
| C2 | 方向分 == Σ(优势分×权重)÷100 | **6 场里 4 场对不上** |
| C3 | 站边方向与方向分符号一致 | **1 场矛盾** (根因是 C2) |
| C4 | 比分方向与站边一致 | 通过 |
| C5 | 置信度分跨场次有区分度 | **6 场全是"中"** |
| C6 | **反编造**: 证据里的日期必须在证据包里找得到; 情报标"未获取"时不许出现伤停断言 | 通过 |

### 5.1 C2 的教训 —— 计算权必须收回来

第一版让 LLM 自己输出 `方向分`。实测 **6 场里 4 场算错**, 其中土耳其那场**符号都反了**
(自报 +1.40, 实算 −1.47)。

**修法: 方向分改由程序计算, LLM 只负责给每个维度的优势分。** 这样算术错误在结构上就不可能发生,
C2 变成了"验证存储值"而不是"指望 LLM 算对"。

### 5.2 优势分正负号的坑

第一版提示词没说清正负号, LLM 会把**"证据强度"**当成优势分 (证据再强也要问它帮哪一边),
导致"维度分利主队、结论却选客胜"。修法: 写明 `正值 = 对主队有利`, 并给三个例子,
且明确"自相矛盾的输出会被程序判为不合格"。

## 6. 台账与修订

`data/national/calls_ledger.jsonl` —— **只追加, 不修改**。

| 字段 | 说明 |
|---|---|
| `prompt_version` | 提示词/评分逻辑一改就变。决定这条是不是"当前口径" |
| `revision` | 同一场的第几次判断。开场前反复修订是允许的, **开赛后禁止再落账** |
| `stage1_blind` | 第一段的完整输出 (含投票明细) |
| `stage2_vs_market` | 第二段: 关系 / 是否改判 / 我漏掉的事实 / 分歧说明 |
| `final` | 最终站边、比分、置信度分、方向分、**自洽度** |

⚠️ **评分时必须只取每场 `revision` 最大的那条**, 否则同场多条会被算重。

## 7. 已知缺陷 (如实记录)

1. **稳定性只有一次测量** (6 场)。K=3 的多数投票在 2/3 一致时是脆弱的。
2. **没有历史回测**。八维盲判依赖情报, 而情报是**当天抓的**, 无法回溯到 2018 年 ——
   所以这套东西**永远不可能用历史数据验证**。只能靠前向落账攒样本。
3. **和"市场 vs 模型谁强"是同一个样本量问题**: League A 每年新增 48 场, 检出 0.02 的效应要 933 场。
   所以这套方法的价值**不能靠统计显著性来证明**, 只能靠长期的落账记录给人看。
4. 情报覆盖不齐: 本轮 6 场里, 葡萄牙 vs 威尔士和荷兰 vs 德国**情报基本没抓到**。

## 7.5 判据与打分 (2026-09-24 用户拍板)

**主判据 = 只考核「反向」场次。**

理由: 同向场次我们只是在附和市场 —— 在那里赢市场不算本事, 输市场也不丢人。
**只有"我们和市场反着来"的场次, 才是这套方法真正在下注。** 每季约 16 场。

打分器: `python national/score_calls.py [--date ...]`

它会:
- 从台账取**每场 revision 最大**的一条 (只追加不修改, 靠 revision 去重)
- 从语料读赛果, 容忍 ±1 天 (语料记当地日期, 体彩记比赛日; 欧洲晚场两者一致, 但不赌)
- 分三块报: **反向场次 (主判据)** / 同向场次 (参考) / 全部
- 额外报 **自洽度 → 命中率**: 3/3 一致的场次是不是真的比 2/3 的准。
  这是"自洽投票到底有没有意义"的检验 —— 没有这个, 投票就只是仪式
- B 轨对照 (`run_nl.py` 的 DC + 市场融合)

⚠️ **显著性永远拿不到。** League A 每年只新增 48 场, 反向场次约 16 场。
这套方法的价值**不能靠 p 值证明**, 只能靠长期台账给人看。**单轮数字没有统计意义。**

### 成本 (2026-09-24 我算完改了主意)

我原本提议"只在 DC 与市场分歧 ≥8 个点时才跑八维"。算完发现**不划算**:
每季 48 场 × 4 次调用 = **192 次/季**, DeepSeek 这个量级成本可忽略。
而按分歧门控会**毁掉完整记录**, 且用 DC 分歧当代理与"我们和市场分歧"(只有跑完才知道)是两回事。
→ **默认全跑**。`--only-divergent <百分点>` 作为可选项留着备用。

## 8. 与主链路的关系

- **完全独立**。`national/octa.py` 只在 `national/` 内, 不碰 `pipeline/analyst.py`。
- 它**不经过市场融合** (w=0.10 那套)。它的输出是**我们的判断本身**。
- 现有的 `run_nl.py` (DC + w=0.10 市场主导) 保留, 作为**对照轨**:
  它代表"纯数据 + 市场", 八维盲判代表"情报 + 独立判断"。两条轨都落账, 将来一起打分。

## 9. 操作方式

```
# 出判断 (每场盲判跑 3 次取多数)
python national/octa.py --date 2026-09-24 --repeats 3

# 先试跑不落账
python national/octa.py --date 2026-09-24 --only 挪威 --dry-run

# 自检 (必跑)
python national/check_calls.py --date 2026-09-24

# 赛果进语料后打分 (主判据 = 反向场次)
python national/refresh_corpus.py && python national/score_calls.py

# 省钱模式: 只跑 DC 与市场分歧 >= 8 个点的场次 (默认全跑)
python national/octa.py --date 2026-09-24 --only-divergent 8
```

情报来源: `data/national/intel_<日期>.txt` —— 由**主代理用 web_search 抓**并写入,
不是爬虫。原因见 `docs/欧国联预测方案.md` 第 9.2 节 (cn.bing 通道已失效)。
